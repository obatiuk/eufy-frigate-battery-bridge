# `AT-13`: Per-Station `P2P` Priority Preemption, Preempted Event Backfill & Instant Back-to-Back Switching

- When two `P2P` sessions compete for the same HomeBase `P2P` slot:
  1. Any live `P2P` motion/event request (or `/api/wake` with `create_event: true`) must immediately preempt an active
     in-transfer `Backfill` download (`STREAM_MODES.DOWNLOAD` while `!downloadFinished`), whereas viewer-only wakes must
     **never** preempt an active `Backfill` download (`isUrgentBackfillProtectedFrom`), and once the `HomeBase 3`
     clip transfer finishes (`downloadFinished: true`, draining from RAM), the camera releases the `HomeBase` `P2P`
     channel (`isOccupyingStationP2pChannel() === false`) so other cameras on the same station can use `P2P` in parallel
     without stopping the draining backfill playback.
  2. A `P2P` motion/AI/ring event must immediately preempt a viewer-only `P2P` session.
  3. A higher-priority `P2P` event (`camera.priority + event_priority`) must immediately preempt a lower-priority `P2P`
     event, and an equal-priority newer `P2P` event must preempt an older one when `view_has_priority: true`
     (default).
  4. Whenever an active event-driven `P2P` session is preempted early while its event/motion is still active, the
     preempted camera **must** retain or re-queue its `BackfillJob` so the full clip recorded on HomeBase 3 is
     backfilled afterward, even if `>= 20%` of the hold duration was already streamed live before preemption.
  5. Back-to-back live streaming on the same station (when a waiting camera starts immediately after another camera's
     session ends) must switch instantly without applying the `2500ms` station wake pacing delay; pacing only applies
     between wake START commands that are not separated by a session end (e.g., external `/api/wake` requests).
