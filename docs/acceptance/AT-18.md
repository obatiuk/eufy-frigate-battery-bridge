# `AT-18`: 6-Color Status Palette, Debug HUD Service Statuses, Snapshot Isolation, `hwaccel` Fallback & Config Clamping

- For status card overlays, encoder frame pacing, media pipeline resilience, and configuration validation:
  1. The bridge must support all 5 `card_theme` values (`"icons"`, `"minimal"`, `"detailed"`, `"debug"`, `"none"`),
     throttle sleeping frames to `idle_fps` (`5 fps`) and active frames to `live_fps` (`15 fps`), and enforce the
     6-color semantic status palette across all card themes without mutating `lastFrame`:
     - **Green (`#4ade80`)**: `Asleep` (sleep-ready with all services healthy: `eufy-security-ws`, `HomeBase`/camera,
       `Frigate`, and `go2rtc` connected).
     - **Purple (`#e879f9`)**: `Asleep (Low Battery)` (`<= low_battery_threshold` unplugged while healthy).
     - **Yellow (`#facc15`)**: `Waiting` (waiting for a station `P2P` slot, while `IDLE` with a pending `BackfillJob`,
       or during `HANDSHAKING_BACKFILL` before Frame 0 decodes).
     - **Blue (`#38bdf8`)**: `Waking Up...` (initial wake handshake before first video frame).
     - **Red (`#ef4444`)**: `Live` (`L` / Play) or `Backfill` (`FB` -> `B` / Rewind).
     - **Grey (`#b4b4be`)**: `Disconnected` (whenever `eufy-security-ws`, `HomeBase`/camera, `Frigate`, or `go2rtc` is
       down/disconnected), as well as `Not available` for Battery, Wi-Fi, or Temperature icons/dots when a sensor value
       has not been reported.
       In `"debug"` theme (`buildDebugHudLines`), Row 1 Column 6 must display the 4 service statuses
       (`WS:OK HB:OK FRG:OK RTC:OK`, switching each to `DN` when down) directly above `HW:...`, and Row 3 Column 6 must
       display `TRIG:<STATE>  <SECS>  Q:<LIVE>/<DL>`.
  2. Snapshot cache files must be strictly isolated per camera (`last_<name>_<serial>.jpg`), must never read Eufy's
     `properties.picture` station-cached thumbnail, must hold the last decoded video frame (`frame || lastFrame`) during
     mid-session re-wakes and teardown once `gotVideo` is true so `"Waking Up..."` never flashes after video starts, and
     must run a `2s` startup snapshot probe only when a camera is online with `sleep_screen: "snapshot"` and no cached
     snapshot on disk (or `startup_snapshot: "always"`).
  3. The media pipeline must scale mid-stream resolution shifts (`360p` -> `1080p` / `2K`) in-band without restarting
     the `ffmpeg` decoder (restarting only on `H264 <-> H265` codec changes), pad non-`16:9` streams when
     `preserve_aspect_ratio: true`, and automatically fall back from GPU encoding (`hwaccel`) to software `libx264` on a
     camera if `ffmpeg` exits within `5s` of spawn with a hardware/driver error.
  4. Configuration validation must require only `eufy_security_ws_url`, `frigate_url`, and `cameras` (while allowing an
     optional `"$schema"` property in `validateConfig()`, with IDE schema validation provided by
     `deploy/config.schema.json`), strip any trailing `/` or `/api` from
     `frigate_url` and `go2rtc_url`, auto-derive omitted `go2rtc_url` (`http://<frigate-host>:1984`) and
     `rtsp_output_url` (`rtsp://<host>:8554/{name}`, auto-appending `/{name}` when a base RTSP URL is provided), support
     pure upstream legacy configurations (`eufy_ws`, `go2rtc_api`, `rtsp_publish`, `frigate_api`, `ha_webhook`,
     `max_secs`, `min_dwell_secs`, `viewer_cooldown_secs`, `event_secs`, `snapshot_delay_secs`) with a deprecation
     warning and default `mode: "auto"`, reject mixed legacy + new or unknown keys by reporting all validation issues in
     one error message, resolve all 5 camera modes (`"auto"`, `"rtsp"`, `"p2p"`, `"backfill"`, `"custom"`), default
     omitted `name` to `serial` and omitted `title` to Eufy's device name, and enforce defensive clamping
     (`idle_fps <= live_fps`, `stream_max_secs >= hold_secs`, `view_max_secs >= view_linger_secs`,
     `low_battery_hold_secs <= hold_secs`, `backfill_enabled = true` in `"backfill"` mode, and auto-promoting
     `power_working_mode` to `2` when custom clip settings conflict with mode `0`).
