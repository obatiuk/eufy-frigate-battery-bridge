# `AT-11`: Mid-Stream Hold Extensions Across All Modes & Signal Sources

- Whenever a camera is **already streaming live** (`STREAMING_LIVE` in any mode, including a `"backfill"` camera
  currently streaming Live View or `/api/wake`):
  1. Any new Eufy trigger event (`motion`, `person`, `ring`), mid-stream `'livestream started'` /
     `'rtsp livestream started'` re-trigger, or active Eufy hardware trigger / Frigate object detection near timeout
     must extend the active hold by `hold_secs / 2` (or a full `hold_secs` when a new trigger arrives in the second half
     of the hold window), clamped to the camera's configured `stream_max_secs`.
  2. Calling `POST /api/wake/:cameras` on an already-streaming camera must extend the active hold to at least
     `now + duration` (clamped to `stream_max_secs`).
