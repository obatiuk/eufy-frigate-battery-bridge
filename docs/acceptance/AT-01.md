# `AT-01`: `"backfill"` Mode on `RTSP`-Capable Cameras - Motion, `/api/wake` & Hardware Events While `IDLE`

- When a camera configured with `mode: "backfill"` supports HomeBase native `RTSP` (with `rtspStream` /
  `rtspStreamUrl`) and is `IDLE`:
  1. Eufy motion, person, pet, vehicle, sound, or radar trigger events (`state: true`) **must never** wake a live
     `RTSP` or `P2P` session. The camera must remain `IDLE`, queue a `BackfillJob`, and display the **Yellow**
     (`Waiting` / `busy`) status indicator until backfill playback starts or the job expires. If
     `POST /api/wake/:cameras` arrives while a Eufy hardware trigger or `BackfillJob` is already active, it must also
     stay `IDLE` and upgrade/extend the `BackfillJob` (`status: "backfill"`).
  2. When the camera hardware emits `'rtsp livestream started'` (or `'livestream started'` while a motion/AI/ring
     trigger or `BackfillJob` is active) while `IDLE`, the bridge **must never** adopt it as a live session, **must
     never** call `device.stop_rtsp_livestream`, and **must never** set `rtspStream: false`. Instead, it must queue or
     extend the `BackfillJob` time window (and mark that trigger cleared on `'rtsp livestream stopped'` /
     `'livestream stopped'`) so HomeBase 3 is queried and any recorded `.zxvideo` clip is replayed via backfill.
  3. When a standalone `'livestream started'` event arrives while `IDLE` outside the `3s` post-sleep guard with **no**
     active Eufy motion/AI/ring trigger or pending `BackfillJob` (e.g., a human opened Live View in the Eufy mobile
     app), the bridge **must** piggyback on the already-flowing `P2P` stream (`p2pReady: true`, without sending
     `device.start_livestream` or `device.start_rtsp_livestream`) and stop immediately when `'livestream stopped'`
     arrives.
