# `AT-17`: `POST /api/wake/:cameras`, Frigate Event Snapshots/Extensions, Auto-Masks & `HA_WEBHOOK_URL`

- For external API wakes and Frigate/Home Assistant integration:
  1. `POST /api/wake/:cameras` (and `GET /api/wake/:cameras`) must resolve `all`, camera `name`, `serial`, or
     slugified `title`, sort `RTSP` cameras before `P2P`, wake an `IDLE` `"backfill"` camera live when no Eufy trigger
     or `BackfillJob` is active (staying in backfill mode and queuing/upgrading the `BackfillJob` with
     `status: "backfill"` when a Eufy trigger, pending `BackfillJob`, or active `isBackfillPlayback()` is in progress on
     a `"backfill"` camera, and on a `"p2p"`, `"rtsp"`, or `"auto"` camera in `isBackfillPlayback()` either upgrading
     the `BackfillJob` with `status: "backfill"` when an unexpired Eufy hardware trigger is recording or deferring the
     live wake with `status: "scheduled"` until backfill playback finishes so chronological event order is preserved),
     pace live wakes on the same HomeBase by `2.5s`, coalesce duplicate bursts, and file a Frigate event unless
     `create_event: false`.
  2. For direct `rtsp_url` (`isRtspDirect()`) cameras and HTTP error handling on `/api/wake/:cameras`:
     - **Hybrid direct `rtsp_url` handling:** Explicitly targeting only direct `rtsp_url` camera(s) must return `422`
       (`ok: false`, `error_code: "UNSUPPORTED_OPERATION"`, `results[].status: "unsupported"`), whereas `all` or mixed
       targets containing Eufy cameras must skip direct `rtsp_url` entries with `status: "unsupported"` inside `200`
       `results[]` without starting streams, touching `stationNextWakeAt`, or filing Frigate events.
     - **Atomic targets & strict input/state errors:** Partial or full unknown camera names must fail atomically with
       `404` (`CAMERA_NOT_FOUND`, `unknown`, `available`) before waking any camera; malformed URL encoding, invalid
       JSON/non-object bodies, or invalid `duration`/`create_event`/`reason` parameters must return `400`; bodies over
       `16384` bytes must return `413`; unsupported HTTP methods must return `405` (`Allow: POST, GET`); and
       `eufy-security-ws` disconnect (`WS_DISCONNECTED`), bridge shutdown (`BRIDGE_SHUTTING_DOWN`), or all-offline
       wakeable targets (`CAMERA_OFFLINE`, still triggering `driver.poll_refresh`) must return `503`.
  3. Frigate events must wait for the first real video frame to reach Frigate (`~1s` live, `0.8s` backfill) or inject
     the clean cached snapshot (`suppressLiveCard`) if a wake times out without video, upgrade/extend when companion
     triggers or hold extensions exceed `evUntil`, auto-sync the status card polygon to Frigate's `motion.mask` and
     `objects.mask` when `auto_frigate_mask: true` (deleting bridge-created `eufy_bridge_card` masks for
     `card_theme: "none"` or `card_position: "center"` while leaving user-defined masks intact), and send both initial
     and follow-up `HA_WEBHOOK_URL` POSTs when configured.
