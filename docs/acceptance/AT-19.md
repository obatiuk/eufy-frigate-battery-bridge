# `AT-19`: YAML Config Validation, Env Endpoints, Direct `rtsp_url` Resolution, Clamping, Warnings & `/api/config`

- For configuration validation, environment resolution, mode resolution, clamping, and runtime inspection:
  1. `validateConfig()` must require `cameras` with at least one valid camera entry (`serial` or `name` + `rtsp_url`),
     reject unknown top-level or camera keys (including removed legacy or environment-only keys), validate `rtsp_url`
     protocols (`rtsp://` or `rtsps://`) and compatible modes (`"auto"` or `"rtsp"`), and report all validation
     issues in a single error message. `loadConfigFile()` must parse `YAML` (`config.yaml` / `config.yml`), expand
     `${ENV_VAR}` and `${ENV_VAR:-default}` placeholders cleanly, and resolve `BRIDGE_CONFIG` when configured.
  2. `resolveServiceEndpoints()` and `BridgeConfigBuilder` must resolve `EUFY_WS_HOST`/`EUFY_WS_PORT`/`EUFY_WS_URL`,
     `FRIGATE_HOST`/`FRIGATE_PORT`/`FRIGATE_URL` (stripping trailing `/` and `/api`),
     `GO2RTC_HOST`/`GO2RTC_API_PORT`/`GO2RTC_RTSP_PORT`/`GO2RTC_RTSP_USER`/`GO2RTC_RTSP_PASSWORD`/`GO2RTC_URL`/
     `GO2RTC_RTSP_URL` (auto-deriving `go2rtc` host from Frigate and building `rtsp_publish_url` ending in `/{name}`),
     `HA_WEBHOOK_URL`, `BRIDGE_LOG_LEVEL`, `BRIDGE_HTTP_PORT`, `BRIDGE_CACHE_DIR`, `BRIDGE_HWACCEL`, and
     `BRIDGE_HWACCEL_DEVICE` with environment variables taking strict precedence.
  3. Camera configuration resolution must support all 5 camera modes (`"auto"`, `"rtsp"`, `"p2p"`, `"backfill"`,
     `"custom"`, warning and falling back to `"auto"` on unknown mode names), resolve `"auto"` or omitted `mode` to
     `"rtsp"` when `rtsp_url` is set, disable `backfill_enabled`, `sync_power`, `startup_snapshot`, and `telemetry`
     (`enabled: false`) when `rtsp_url` is set (narrowing `"minimal"` to the `26x12` status pill), default omitted
     `name` to `serial` (and omitted `serial` to `name` internally when `rtsp_url` is set), and default omitted `title`
     to Eufy's device name (falling back to `name` until discovered or on direct `rtsp_url` cameras).
  4. The bridge must enforce defensive non-contradiction clamping (`idle_fps <= live_fps`,
     `stream_max_secs >= hold_secs`, `view_max_secs >= view_linger_secs`, `low_battery_hold_secs <= hold_secs`,
     `0 < critical_battery_threshold < low_battery_threshold <= 99`, `backfill_enabled = true` in `"backfill"` mode,
     `recording_clip_length >= hold_secs` when `end_early: false`, and auto-promoting `power_working_mode` to `2` when
     custom clip settings or `hold_secs > 20` / `end_early: false` conflict with mode `0`).
  5. Startup initialization must log a warning whenever any explicitly specified environment, top-level, or per-camera
     option is ignored (including Eufy/timeout/backfill/power/telemetry options on direct `rtsp_url` cameras or when all
     cameras specify `rtsp_url`, `backfill_only` outside `"custom"` mode, `use_rtsp` when overridden by `"rtsp"`/`"p2p"`
     mode, `idle_timeout_secs` in backfill-only mode, Power Manager clip/mode options when `sync_power: false`,
     card/telemetry options when `card_theme: "none"`, `card_position: "center"`, `card_theme: "minimal"`, or
     `telemetry.enabled: false`, `startup_snapshot` when `sleep_screen` is `"slate"` or `"black"`, and
     `BRIDGE_HWACCEL_DEVICE` when `BRIDGE_HWACCEL` does not use a device node), and `GET /api/config` must report the
     active effective configuration with URL credentials masked as `"***"` and `null` for all inapplicable fields.
